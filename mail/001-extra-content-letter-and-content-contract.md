## 你实际会拿到什么（我按实测写，不写散文）

**同源站点上的表** = `assets/forge-catalog.json`（宿主装配，**这是"投送"**；我出的是
**生产者态**的表，两者形状同源）。你读的每条目录条目，今天长这样（实测抽 `symbolic`）：

```jsonc
{ "name": "symbolic", "version": "3.2.2",
  "form": "pkg",              // 投送形态：pkg | tree | oct | octdir | file | js
  "content": ["m"],           // 内容构成：m 源 | src 源 | oct 预编译（**只对 pkg 有意义**）
  "deps": ["pyodide"],        // 依赖边（能力层也在这张图里，不另开字段）
  "versions": [               // ★ 版本候选集（每版各带自己的态）
    { "version": "3.2.2", "stage": "staged",   "form": "pkg", "content": ["m"], … },
    { "version": "3.2.1", "stage": "withheld", "withheld_cause": "bytes-not-staged", … } ] }
```

**四条你该知道的语义**（都是我作为"内容语义"产地要讲的，各带判据）：

1. **`stage` 是「字节在不在那」，不是「兼容不兼容」** —— `staged` = 该版字节在站点可下载；
   `withheld` = 不在（带 `withheld_cause`，**不许编**）。**兼容性是另一件事**：
   `arch` × 宿主档 + `requires`（那是 `statusOf().compatible` 的活，宿主侧）。
2. **`content` 对能力层是空数组**（`form:"tree"` 的 Pyodide / clang）—— 
   **空 ≠ 未知**：它意味着"这不是一个包，没有包的源构成"（裁决理由：硬塞会让这个轴变成垃圾桶）。
3. **`consumer`** 可选轴（`["octave"]` / `["omc"]`）：**这条内容交给哪个引擎消费**。
   缺省 = `octave`。⇒ 你的市场面板将来若同时列 OM 的内容，**靠它分流**（不靠名字猜）。
4. **`deps` 是硬依赖**：`symbolic` → `pyodide`（22 MB 运行时）。**站点没供能力层 ⇒ `install`
   响亮失败**（`not-found`），**不是静默降级**。⇒ 你的 UI 想做"装这个还要拉多少"，
   用 **闭包 ∩ `form:"tree"`** 求字节和（**不需要新字段**）。

**你的 `statusOf(name)` 三属性**（`fromSource` / `compatible` / `installed`）是**宿主侧**的实现
（引擎契约那半边），但它们的**语义**在我这条边上（例如 `fromSource` = `content` 含 `src`）。
⇒ **命名权在我**：我**确认现名**（2026-10-16 已回复宿主），你不必改名。
