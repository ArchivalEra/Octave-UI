# mail/ · 跨 agent 通信（本仓的**收件箱**）

> **这是什么**：其他 agent / 仓库写给**本仓（Octave-UI）**的信。一封信 = 一个文件，
> **只追加，不删**（它是往来记录，不是工单）。
>
> **规矩来源**：四仓（`Octave-Full-Wasm` / `Octave-Extra-Content` / `LLVM-wasm` /
> `OpenModelica-Full-Wasm`）已在用的同一套机制（2026-10-15 用户点令「各家只读自己的
> mail 文件夹」后立规）。本仓补上收件箱 = 把投递方向摆正。

---

## 四条规则（可执行）

1. **投递落点 = 收信方的 `mail/`** —— 写给**本仓**的信落进**本仓** `mail/`；
   写给别仓的落进**它仓**的 `mail/`（不留在发信方自己仓里当"我发出去的"）。
2. **只读自己箱子** —— 本仓只读**本仓** `mail/`；**不读别仓的 `mail/`**
   （即使那仓 public，那也是别人的私人通信）。
   ⚠️ **一个写明的例外**（2026-10-16 实测可达性）：**对方明确投给本仓的信**（`**To:**` 指名本仓）
   若落在对方仓（因为本仓 private、对方推不进来），**读它是收信、不是越界**。
   判据很窄：**`To:` 指名本仓**才算。泛指 / `To:` 别仓的照旧不读。
3. **`To:` 必须指名收件方** —— 本仓 `mail/*.md`（除本 README）的 `**To:**` 必须指名**本仓**
   （`Octave-UI` / `ui`）。一封 `To:` 别的仓的信出现在这里 ⇒ 投递方向错了。
4. **投递 ≠ 提交** —— **投递 = 落文件**（写进收信方 `mail/`）；**提交/推送 = 收信方做**
   （那是它的仓、它的闸门）。发信方若**能满足收信方的闸门**（如本仓是单条目 README）
   才可代为提交；不能满足就不提交。

> 根因记录：四仓里 `Octave-Full-Wasm` 曾**唯一没有 `mail/`** ⇒ 写给它的信无处可投、
> 只能落回发信方仓 ⇒ 逼它去翻别仓目录找信（越界）。**补上收件箱 = 把投递方向摆正**；
> 本仓按同一规矩补箱（2026-10-16，由额外内容仓投递时建立）。

## 命名

```
mail/NNN-<from>-<topic>.md       来信（NNN 三位递增，本仓内唯一）
mail/NNN-re-<topic>.md           回信（编号接被回的那封；`re-` 前缀标明是回复）
```

- `<from>`：发信方短名（`extra-content` = Octave-Extra-Content、`host` = Octave-Full-Wasm、
  `llvm` = LLVM-wasm、`om` = OpenModelica-Full-Wasm）。
- 编号**只看顺序**，不与 `questions/` 共享。

## 一封信里必须有的

1. **头**：`To` / `From` / `Date` / `Re`（一行说清问什么）；
2. **发信方看到的事实**（引路径 / 命令 —— 断言旁写复跑方式）；
3. **具体问题**（编号 `Q1/Q2…`，每题**可答**：是/否/二选一，或"给一条命令"）；
4. **发信方自己认下的东西**（若这封信暴露了发信方的错，写在这里）。

## 回信的纪律

- **逐题回**（`A1/A2…` 对齐 `Q1/Q2…`）—— 漏答比答错更难查；
- **改了本仓什么就写路径**（回信是"边界动没动"的凭据）；
- **分歧不要静默**：不同意就写"不同意 + 判据"，别把信压着不答。

## 与闸门的关系

本目录**不进**任何闸门的断言面（它是散文往来，不是事实台账）。
但**由信催生的结论**若改变了本仓的角色/契约，必须落进 `README.md` / `CONTEXT.md` /
`STATE.md` 的**活状态**（那才是会被闸门对账的地方）。
