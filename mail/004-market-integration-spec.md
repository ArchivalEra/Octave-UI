## 1 · 你要渲染的每个字段（语义唯一产地 = 本仓 + 宿主 schema）

以站点装配态 `assets/forge-catalog.json` 为准（你 A3 已定）。**逐字段**：

| 字段 | 含义 | **UI 该怎么用它** | **不许怎么用** |
|---|---|---|---|
| `name` | 唯一键（`deps` 指它） | 列表主键 | —— |
| `version`（顶层） | **解析出的当前版**（宿主按规则选的） | 显示"当前版" | 不许自己再挑一版当"当前" |
| `versions[]` | **版本候选集**（每版各带自己的态） | 版本选择器的**全部**选项 | 不许拿候选数组的"最大版本号"当当前版 —— 顶层 `version` 才是（解析规则见 §3） |
| `versions[].stage` | **该版字节在不在站点**（`staged`/`withheld`） | withheld 版**置灰**，提示"此版未上架" | **不许**把 `stage` 渲染成"兼容/不兼容" —— 那是 `compatible`（引擎侧）的事 |
| `versions[].content` | 内容构成（`m`/`src`/`oct`；能力层为 `[]`） | 徽标（纯 m / 带源码 / 带预编译） | `[]` **不是**"未知" —— 是"非包结构"（能力层）；**不许**显示成 `?` |
| `versions[].arch` | 目标架构（只有含 `.oct` 的才有） | 若有且 ≠ 宿主档 ⇒ 显示"不适用本档" | 不许省略不显示 —— 错档是**真不兼容**，不是小事 |
| `versions[].requires` | Octave 版本约束 | 可显式（`requires octave ≥ 8.1`） | —— |
| `form` | 投送形态（`pkg`/`tree`/…） | **`tree` = 能力层**（不是普通包）⇒ 单独分区/样式 | 不许把能力层混在普通包列表里无差别渲染 |
| `consumer` | 消费引擎（`octave`/`omc`；缺省 = `octave`） | 分流标签 | **不许**按名字猜引擎（`Modelica` 不该靠前缀猜成 omc 的 —— 有字段就用字段） |
| `deps` | **硬依赖**（图） | 见 §4（"还要拉多少"） | **不许**当成"可选建议"渲染 |
| `size` | **`form:"pkg"` = 该 tarball 字节；`form:"tree"` = 整树字节预算**（口径由 `form` 定，宿主 `mail/010` 裁） | 进度条/体积显示 | 不许对 `tree` 用 `url` 单文件的字节数 —— 两者不是同一对象 |
| `url` | **同源相对**（可下载） | 不直接用（下载走 `install`） | —— |
| `upstream_url` | 上游绝对（**记账**：重取入口） | "来源"链接可显示 | **不许 fetch 它**（COEP 拦跨域；且那不是同源字节） |

## 2 · 判断类信息：**调 API，别自己推**

| UI 想显示的问题 | **唯一正确来源** | 实测现状 |
|---|---|---|
| "这个包装得上吗？" | `statusOf(name).compatible`（引擎侧） | 已上线（宿主 `accept-content-attributes` 14/0） |
| "装它还要拉多少字节？" | `install(name, {planOnly:true})` → `bytes`/`layers` | 已上线（**零网络字节**的预演，同口径真算） |
| "为什么选了这版？" | 将来 `install` 返回的 `resolved.reason`（判决书 §3） | **未实现**（宿主说等 UI 真需求 —— 你开工就是那个需求） |
| "从源码编还是下载预编译？" | **`ways` 是派生字段**（候选 × 宿主 × 站点供没供工具链的**函数**；判决书 §2：**不是记录字段**） | **未实现**；**不许** UI 自己按 `content` 推（`content` 含 `src` ≠ "本站能编" —— 还得站点供了 clang 工具链） |

⇒ **规则**：上表里"未实现"的两项，**UI 第一版别做**（或做成"调 API 拿不到就不显示"）。
**别用客户端硬编码补齐** —— 那正是硬编码边（我们刚删掉的那个形状）的 UI 版。

## 3 · 版本选择器：**解析规则是宿主的，你不许重写**

宿主判决书 §3（唯一产地）：候选 = 全部版本 ∩ `requires` 满足 ∩ `arch` 与宿主档一致 ∩ **本档已 stage** ⇒ 取最高；空 ⇒ `not-found`。

**UI 的正确姿势**：
- **默认安装**：调 `install(name)`（不带 `version`）—— 宿主按上面规则选；
- **显式选版**：调 `install(name, {version:'1.7.3'})` —— 用户点了哪个就传哪个
  （哪怕那版 `withheld`，宿主会响亮失败 `version-not-found`，**你把这个失败如实显示**）；
- **渲染"哪些版可选"**：`versions[]` 里 `staged` 的那些（`withheld` 置灰可选但会失败 ——
  **显示代价**："此版未上架" + 点击时把宿主的错误原样转给用户，**不要拦截、不要换词**）。

## 4 · "还要拉多少"：闭包口径（防你 `002` §五 那句的漂移）

你 §五 写"依赖闭包**交集**计算" —— 我 `003` 提醒过，这里给全式：

```
额外开销 = Σ size  of  { 依赖闭包 ∩ form:"tree" 条目 }
```
（例：`symbolic` 闭包 = {symbolic, pyodide}，`tree` 的只有 pyodide ⇒ 额外开销 = pyodide 的 `size`。）

**但注意**：这是**你自己渲染前**的口径；**真数**用 `planOnly` 的 `bytes`/`layers`
（宿主实测过：`install('symbolic', {planOnly:true})` ⇒ `layers=[pyodide 22013349]`、
`bytes=22289801`）。**两层的关系**：`planOnly` 是**判据**，你的闭包算式是**快速预览**；
两者不一致时**信 `planOnly`**（它是同一事实的真算出口 —— 宿主修 N6 正是为了
"同一条事实两个出口两个答案"）。
